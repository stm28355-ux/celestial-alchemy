## 作り方

| 項目 | 決めたこと |
|---|---|
| 形 | 静的HTML＋JavaScript（ESモジュール）。ビルドなし。`index.html` を開けば動く（ローカルでは `npm run serve`） |
| 描画 | 盤面は canvas、手持ち・メニューは HTML |
| ルール | 落ちる・反応・処理の順番は、画面と分けて `src/core/` に置く。画面なしで動き、テストとソルバーが同じコードを使う |
| ソルバー | `npm run solve`：ステージが解けるか、解がいくつあるか、狙いの手順以外で解けないかを出す |
| ステージ | テキスト形式（盤面は文字の並び）。形式の版番号を入れる |
| 共有 | ステージを圧縮して、URL の `#` 以降に載せる（ブラウザの標準の圧縮を使い、ライブラリは入れない） |
| 重い処理 | ヒントとランダム生成は Web Worker で動かし、画面を止めない。依頼の掲示板は前もって生成して同梱する |
| セーブ | ブラウザの localStorage（端末ごと）。クリア済みと、作ったステージ |
| テスト | `npm test`（Node の標準テスト）。素材ごとのルールと処理の順番を、小さな盤面で守る |
| 公開 | GitHub Pages（main ブランチの一番上のフォルダ）。リポジトリは公開（Pages を無料で使うため） |
| 進み具合 | GitHub の Milestones ＝ フェーズ、Issues ＝ やること・未決事項。この計画書の表も更新する |
| スマホ | 動いたらよい程度。合わせ込みはしない |
| 言語 | 日本語だけ |

### フォルダ

```
index.html, style.css      画面
src/core/                  ルール（盤面・落ちる・反応・処理の順番）とソルバー ※画面なしで動く
src/data/                  素材・ステージ・章・依頼文
src/ui/                    描画と操作
stages/                    ステージのテキスト（章ごと）
test/                      テスト
tools/                     開発用サーバー・ソルバー・生成器
docs/                      この計画書など
```

### フェーズ0で決めること

2026-11-14 に、2以外はおすすめのまま決めた。

1. **ピースの素材**：1つのピースは1つの素材だけ（おすすめ）。1つのピースに素材を混ぜない
2. **ピースの大きさ**：まず1〜4マスで作る。足りるかは、フェーズ2でステージの中身を決めるときに考える（2026-11-14）。仕組みは大きさを決め打ちしない
3. **向き**：回転の4向きだけ（おすすめ）。裏返しはしない（考える数が倍になるため）
4. **盤の大きさ**：幅は最大8、高さは最大10（おすすめ）。縦長の画面でも収まる
5. **最初から盤にある素材**：置いてよい（おすすめ）。例：最初から鱗が浮かんでいる、枠側の氷
6. **手持ちの数**：1ステージ3〜8個（おすすめ）
7. **依頼の掲示板の問題数**：難しさ3段階×40問＝120問（おすすめ、仮）

## フェーズ0：土台（済、2026-11-15）

作ったもの：
- ステージのテキスト形式（版1）。書き方は `src/core/stage.js` の頭に書いた。見本は `stages/sample/`
  - terrain：`#` 壁、`.` 空きマス、`+` 目標マス、`G` 金で埋めるマス、`L` 鉛のまま残すマス
  - pieces と legend：最初から盤にある素材（`fixed` で動かない＝枠側の氷）
  - hand：「素材 形」（例：`lead ##/#.`）。solution：「手持ちの番号 r向き x列」
  - 生の形は JSON（盤面は文字の並びのまま）。共有URLにはこれを載せる
- ルール（`src/core/rules.js`）：落とす、形を保って落ちる、1段ずつの処理、火種×鱗、枠側の氷、上端より上に置けない、クリア
- ソルバー（`src/core/solver.js`、`npm run solve`）：解けるか、道筋の数、反応を使わない道筋の数、クリアしたときの盤面の種類、最初の1手の候補、狙いの手順の確かめ
- テスト16個。行き止まりの見切りが答えを取りこぼさないことを、小さな盤面200個で「見切りなし」と比べて確かめている

分かったこと：
- 見本の「フタの一手」には、こちらが気付いていなかった2つ目の答え（真ん中を先に入れ、器をひっくり返してフタにする）があった。ステージは必ずソルバーにかける
- 見本の「仮の床」は、クリアしたときの盤面が18種類ある。本番では、狙いの手順以外で解けないように絞る
- ソルバーの速さ（このパソコンで）：5×4・7個（鱗と火種入り）で0.8秒。8×4・鉛8個は全部調べて2.6秒。6×5・11個は30秒で探しきれない。手持ちは8個までに収める
- 行き止まりの見切りは、縦にしか動かない素材（鉛・火種・鱗）のときだけ使う。つる・角笛などを入れるフェーズで見直す

## フェーズ8：生成（作った、2026-11-15。人が遊んで確かめるのを待っている）

人と決めたこと（2026-11-15）：依頼の掲示板は難しい問題だけ。やさしい・ふつうは作らない。まず100問を目標にする（#12）

作り方（`src/core/generate.js`、前に遊ばせて、あとから刻印を彫る）：
1. テーマ（素材の組み合わせ16種：溶ける・枠の氷・連鎖・つる・ゼリー・星砂・底の穴・角笛・金 など）を選び、器の形（床のでこぼこ・肩・棚・外した枠）、最初から置く素材（枠の氷・つる）、手持ち（6〜8個）をランダムに決める
2. 手持ちをランダムに落としていく（置けなくなったら残りは手持ちから外す。5個以上置けたものだけ）。必ず解ける盤面ができる
3. 最後にピースがあるマスを刻印にする（金の問題では、金のマスは金の刻印、鉛のマスはだいたい鉛の刻印）。空いたマスは空きマス
4. 答えが2つ以上なら、空いたマスを全部×印にして1つに絞り、要らない×印は空きマスに戻す。絞れなければ捨てる
5. 手持ちの順番を混ぜる（置く順が見えないように）

難しさ（`difficulty`）：答えの道筋の1手ごとに log2（置ける手の数 ÷ クリアにつながる手の数）を足す（「迷いの量」）。物語の問題で測ると、ふつうの問題は 5〜12、各章の試験は 12.5〜17.6。依頼の掲示板は **16 以上**で、反応を使わないと解けないものだけにした

道具：
- `tools/generate.mjs`：worker_threads で並べて作り、下限以上を JSON で1行ずつ書き出す（26並びで1分に2問ほど）
- `tools/board.mjs`：重なりと「反応なしで解ける」を除き、テーマが偏らないように選んで `stages/board.json`（難しさの順）に。残りは `stages/board-extra.json`
- 画面：タイトルの「依頼の掲示板」→ 一覧（解いた数）→ `#/req/N` で遊ぶ。「新しい依頼を探す」は、board-extra からランダムに1つを共有URLの形で出す（人にも渡せる）。全部解いていたら、その場で作る（Web Worker、1分まで）
- テスト：生成した問題がクリアできて答えが1つ（作れると分かっている種で）。依頼の掲示板は、ふだんは10問おきに1問、`npm run test:board` で全問（数分）。テストは45個

結果（2026-11-15）：
- 26並びで約1時間40分、2回に分けて作った。難しさ16以上は202問、重なりと「反応なしで解ける」（約4分の1）を除くと141問。そこから100問を選び、残り41問を「新しい依頼を探す」に回した
- 難しさは 16〜23.3。テストで全問が「狙いの手順でクリアでき、答えが1つ」を確かめた
- テーマ：枠の氷12・連鎖12・金と星砂12・金11・星砂とゼリー10・ゼリー10・溶ける9・星砂7・つると火5・底の穴5・ゼリーと鱗5・角笛と火1・角笛1。**角笛とつるは、ほとんどできなかった**（ランダムに置くと、押しや伸びで器の外へ出たり、×印でも答えが絞れなかったりする）

人の確認1回目（2026-11-15）：
- 一部に難しいものはあるが、素材の性質を無視した問題が多い（特に星砂）。刻印の形でかなり絞り込めてしまう。作り方が悪い。メインのテーマがないとうまくいかない
- 調べると、素材の約半分は同じ形の鉛に替えても解けた（星砂 33問中18、鱗 38問中25、火種 44問中23、ゼリー 23問中14）
- 原因：①「反応を使う」の確かめが甘い（星砂は落ちれば必ずばらけるので、意味がなくても数えていた）②刻印がランダムな形なので、形合わせで解ける ③難しさの目安が、人が形から絞り込む分を数えていない
- 人の振り返り：難易度は順を追って確かめるべきで、一気に100問は指示の失敗だった → 少しずつ確かめる進め方にする

作り直し（テーマから作る、`makeThemed`）：
- 1問に1つ、メインの気付きを決める。器はすっきりした形（ほぼ全面が刻印）。鉛の組み合わせは全部挙げてためす
- 確かめ：答えが1つ／どの答えでもメインの気付きを使う（`meltFall`・`sandFall`）／メインの素材を同じ形の鉛に替えると解けない
- 溶けるテーマは、最初から置く鱗（とその上の鉛）か枠の鱗の段を使う（物語の2章と同じ）。手持ちだけだと答えが1つにならなかった
- まず2テーマ（溶けて落ちる・星砂は真下に）で、低・中・高の難しさから3問ずつ、計6問を掲示板の「作り方の試作」に出した（`stages/board-trial.json`。並びは難しさの順を混ぜてある）。試作1〜6の難しさ：12.2／17.1／9.7／12.7／5.8／9.1
人の確認2回目（試作1〜6、2026-11-15）：
- 難しい順：2＞4＞3＞1＝5＝6（下の方は差が分からない）。目安（17.1／12.7／9.7／12.2／5.8／9.1）と上の2つは合う。器が大きいほど考えることが増える
- 素材の性質は使うが、少し簡単。刻印の形からは答えが見えず、よかった
- 人の案：答えが2つ以上でも、テーマが守られていればよい（答えを1つに絞るために器が小さくなり、削れている）→ そうする
- 直したこと：`makeThemed` に big（答えは何個でもよい。器を大きく：溶ける 4〜6×4〜5、星砂 5〜6×3〜4、鉛は5個まで）。確かめは「どの答えも気付きを使う」と「鉛に替えると解けない」だけ
- 試作7〜12（大きい器）を足した。難しい側から選んだ。目安と答えの数：7＝18.4（6）、8＝22.3（4）、9＝15.5（1）、10＝17.1（4）、11＝10.3（4）、12＝12.6（3）
人の確認3回目（試作7〜12、2026-11-16）：
- 難しい順：8＞7＞12＞9＞10＞11。1〜6より良さそう。答えがいくつもあっても問題は感じない
- 気になる点：特殊な素材を適当に置いたあと、鉛パズルを始める形になる。調べると、12問中9問で「特殊な素材を全部先に置いても、あとは鉛だけで解ける」置き方があった（試作7は56通り中18）
- 人の考え：
  - A（反応を後半で効かせる）は悪くないが、鱗の下で何かをするやり方は別の反応が要る。鱗と火種なら「高い所の鱗を、どう溶かすか」を考える形が近い
  - B（テーマの組み合わせ）は正しい。特に角笛は唯一の横の動きで、動く距離が大きく、もう一度動く、強い素材
  - C（特殊な素材を増やし、鉛を減らす）も正しい。鉛でないだけで考えることが増える。実質鉛でも解ける問題が少しあるのはよい（ピースの意味の裏をかくこともある）。前の「鉛に替えて解けないこと」は言い過ぎだった
  - D（特殊な素材を先に置ける度合いを目安に）は判断できない → 判断材料として測るだけ（`earlyShare`）
- 作った3テーマ（鉛は3個まで、答えはいくつでもよい）：
  - 高い鱗（`tallIce`）：器の一部の鱗が高い所にあり、上は壁でふさぐ。鱗のマスは×印、下は空きマス。火種を横から届かせる台を積む。気付き `frameMelt`
  - 角笛と鱗（`hornMelt`）：鱗が溶けて角笛が落ちると、もう一度押す。気付き `meltPush`、角笛を鉛に替えると解けない
  - 角笛と火種（`hornFire`）：肩の下の×印にある鱗へ、角笛で火種を押し当てる。気付き `pushMelt`、角笛を鉛に替えると解けない
  - 角笛と星砂（粒を押す）は、ほとんど作れなかったのでやめた
- 試作13〜18：13＝高い鱗 20.2（答え1）、14＝高い鱗 10.8（50）、15＝角笛と鱗 20.1（4）、16＝角笛と鱗 16.4（1）、17＝角笛と火種 18.4（2）、18＝角笛と火種 22.4（2）
人の確認4回目（試作13〜18、2026-11-17）：
- 難しい順：13＞15＞18＞17＞16＞14。目安（20.2／20.1／22.4／18.4／16.4／10.8）とだいたい合う
- 13（高い鱗）は良かった
- 角笛テーマは面白いが、15〜18はパターンで解けてしまった部分がある。角笛の問題は形が大きくなるほかなく、今の作り方の制約では難しい
- 試作は名前や依頼文でテーマが分かってしまうので、名前や情報を変えれば、そこまで気にならないはず
- 人の問い：作る時間を、もう少し改善しないといけないか

生成を速くした（2026-11-17、人の「速くする作業から」）：
- 測り方：`tools/bench-gen.mjs`（決まった種で作り、かかった時間とできた問題を出す）。時間を食う所は `node --cpu-prof` で調べた
- 直したこと：
  1. 「見つかったら止める」探し方 `exists`（ふるい分け用。avoid で「気付きを使わない答えがあるか」）。全部数えるのは、ふるいに残った問題だけ
  2. どの素材でも使える見切り `deadEndAny`：空いた刻印の数が「手持ちのマス＋刻印でないマスにある動けるピースのマス」より多ければ捨てる。テストで、いろいろな素材の盤面300個で答えを取りこぼさないことを確かめた（テスト47個）
  3. ピースの大きさ（size）を覚えておく。時間の約2割がここだった
  4. 火種と消える物がないとき、ゼリーがないときは、となり合わせを調べない
  5. 最初の「解けるか」は2万手で見つからなければあきらめる（次の候補へ）。1つの器でためす鉛の組み合わせは20まで

## フェーズ1：試作（済、2026-11-15）

## 変えないこと（企画まとめから）

- ルールは少なく、一目で分かる。覚えるギミックの物量で押さない
- 素材1つに性質は1つ。表にない組み合わせでは何も起きない。1つのステージに出す素材は3種類まで
- 置いた後に盤面が動く反応にする
- 手持ちは好きな順。落とすときに選ぶのは列と向きだけで、落ちる途中では動かさない
- 処理は1段ずつ（落とし切る → 反応をまとめて起こす → 変わったら繰り返す）
- 着地点の影は出す。反応の結果は予告しない
- クリア条件は「手持ちを使い切る＋目標マスを全部埋める」（7章で金のマス・鉛のマスを足す）
- 点数で競わない。毎日1問の形にしない
- 物語は立ち絵と依頼文1文。明るい雰囲気で、Opus Magnum に寄せない
- 本編のステージは「何に気付かせるか」から作り、ソルバーで「狙いの手順以外では解けない」を確かめる
