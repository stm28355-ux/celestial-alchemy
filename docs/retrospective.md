# Celestial Alchemy 作りのふり返り（2026-11-14〜11-21）

11月14日の夜から8日間で、錬金素材のピースを器に落とす「落ちる＋連鎖のはめ込みパズル」を作り、v1.0.0 として公開した（フェーズ0〜10）。企画はその前に別のチャットで固めた（パズルゲーム 構想メモ → 企画まとめ）。Auto Battler（`auto-battler/docs/retrospective.md`）と Arc-en-ciel Creator（`arc-en-ciel-creator/docs/retrospective.md`）のふり返りの続きとして読む。

## 結論（先に3つ）

- **物語の60問は1日で作れたが、掲示板の100問に4日以上かかった。** ルール・ソルバー・0〜7章は 11/15 の1日でそろった。一方、生成した問題の難しさを合わせる作業は、人が遊んで順位を付けるのを9回くり返した（試作72問）。最後の6問は人が自分で作った。
- **素材が「鉛で代わりがきくか」を、企画の段階で確かめるべきだった。** 星砂は止まると1マスずつの粒にばらけるので、たいてい1マスの鉛を何個か置くのと同じになる。素材の性質が要らない問題が多いと分かったのは、生成した100問を人が遊んだあとだった（素材の約半分は、同じ形の鉛に替えても解けた）。
- **総当たりのソルバーで解けない大きさの問題を、甘く見ていた。** 手持ちが多い問題や大きい器では、答え探しが打ち切りになる。人が作った96〜100番はヒントを出せず、7章の最後の調合は難しさの目安も測れない。器と手持ちの大きさの上限を、ソルバーの限界から先に決めておくべきだった。

## うまくいったこと

- **フェーズ0でルールとソルバーを先に作った。** 物語のどの問題も「答えが1つ」「その素材を鉛に替えると解けない」をテストで守れた。人が遊ぶ前に、別解や抜け道を AI が自分で見つけられた。
- **前作の教訓どおり、中身・見た目・最終の調整を別のフェーズにした。** フェーズ9（見た目）とフェーズ10（公開）は、それぞれ半日ほどで終わった。
- **中身の全体の形を、フェーズ2で表にした。** 全章の気付き62個・69ステージ・名前・ピースの大きさを、人が「判定」ドロップダウンで決めた。0〜7章を1日で作れたのは、この表があったから。
- **番号と理由で答えた。** 「1. 十分機能している、はみ出しも面白い 2. 別解が先に思いつくので仮の床には気付かない」。理由があるので、AI がルールの側から直せた（仮の床は気付きの一覧から外した）。
- **試作を「名前を伏せて」「順位で」答えた。** 「72＞69＞70＞68…」の順位と、「47絶賛、54はただの逆版」の一言で、良いテーマと悪いテーマがはっきりした。名前を伏せる案は人から出た（「名前でテーマが分かってしまう」）。
- **AI の制約が強すぎたとき、人が緩めた。** 「答えが2つ以上でもテーマが守られていればよい」「鉛に替えて解けない、は言い過ぎだった」。これで作れる問題の幅が広がった。
- **止めどきを人が決めた。** 「生成器は無理して入れなくてよい」「解けるなら通しプレイは不要」「スマホは動けばラッキー」。AI だけでは決められない線引きだった。
- **最後の6問を人が作り、共有URLで渡した。** エディタと共有URLを骨組み（フェーズ3）で入れておいたので、人の問題を足す道がすでにあった。
- **前作の教訓「フェーズを閉じる前に残りの Issue を並べる」が効いた。** 刻印の見分けにくさ（#14）はフェーズ7で見つけてフェーズ9のマイルストーンに付け、忘れずに直せた。

## うまくいかなかったこと

| 起きたこと | 原因 | 次はこうする |
|---|---|---|
| 星砂は、1マスの鉛で代わりがきくことが多かった。5章の気付き3つ（フタの下・1粒ずつ落ちる・火種の隣でも消えない）は、その気付きがないと解けない問題が見つからず、お手本だけになった。掲示板でも星砂の問題は33問中18問が鉛で解けた | 「止まると1マスずつにばらける」は、ほとんど「1マスの鉛をまとめて落とす」と同じ。企画では動きの面白さだけを見て、「鉛ではできないこと」を確かめなかった | 企画の段階で、素材ごとに「同じ形の鉛・1マスの鉛では、なぜだめか」を1行で書く。フェーズ0〜1で、小さな器を作ってソルバーで「鉛に替えると解けない問題」が作れるかを素材ごとに確かめる |
| 難しさの調整に、人の手が何度も入った。試作は9回・72問、掲示板の数は 100 → 50 → 83 → 86 → 94 → 100 と変わり、最後の6問は人が作った | 計算の目安（迷いの量）と、人が遊んだ難しさが合わなかった。「目安が高いのに簡単」「似た形ばかり」は、遊ばないと分からなかった。しかも「難しい問題だけ100問」と数を先に決めた | 生成するときは、まず数問で「目安と人の順位が合うか」を確かめてから量産する（目安が合わないなら、目安を直すか人の手で選ぶ前提にする）。数は、作れる量と質が分かってから決める。人が遊ぶ回数の上限（例：試作は3回まで）を最初に決める |
| 大きい問題を、総当たりで解ききれなかった。人が作った96〜100番はヒントなし（21〜62秒で打ち切り）。7章の最後の調合は、壁で部屋に分けて調べる仕組み（solveRooms）を足してやっと確かめられ、難しさの目安は今も測れない | ソルバーの速さの限界（手持ちの数・器の大きさ）を測らずに、エディタの大きさの上限（8×10）や問題の大きさを決めた | フェーズ0で「手持ち何個・器どの大きさまでなら何秒で解けるか」の表を作り、エディタの上限と問題の大きさをそこから決める。ヒントは総当たりに頼らず、作った人がクリアした手順を共有URLに入れて使う形も考える |
| 生成器の速さを上げる作業（11/17）に1日使ったが、ゲームには入れなかった | 「その場で作る」かどうかを決める前に、速くする作業を始めた | 生成器は「同梱するだけ」か「その場で作る」かを先に決める。同梱だけなら、速さは道具の待ち時間で足りる |

| ゼリーのルールを、0〜4章を作ったあとで作り直した（横で触れると止まる・鱗はつるつる） | 今のルールで「ゼリーが決め手になる問題」が作れるかを、確かめずに章を作り始めた | 新しい素材は、章を作る前に「その素材でしか解けない問題」が1つ作れるかを試す（星砂と同じ教訓） |

## 人と AI の役割

- **人が強かったところ：** 遊んで分かる面白さ（「47絶賛」「角笛が2つ同時に動くのが良い」）、「鉛パズルになっている」という見抜き、名前を伏せる・制約を緩めるといった作り方の案、止めどき、最後の難しい問題を自分で作る。
- **AI が強かったところ：** ルールとソルバーを先に作り、60問を1日で「答えが1つ」まで確かめて作る、何百問を作って選ぶ道具、立ち絵を SVG で描く、計画のメモと企画まとめの書き足し。
- **AI が弱かったところ：** 「この問題は遊んで面白いか」「難しく感じるか」を数字で当てること。迷いの量の目安は、人の順位と合わなかった。

## 次のゲームで使う手順

前作の12の手順に、今回の教訓を足した（13〜16）。

1. 好きなゲームの面白さを抜き出し、別のチャットで企画を固める。企画まとめ（Docs）を「正」にして、作るチャットにはリンクを渡す。
2. 企画に「変えないこと」と「ジャンルのお約束」を書く。
3. 中身の全体の形を表で決める。
4. 名前と見た目の方向を早めに決める。
5. フェーズは「中身を足す」「見た目」「最終の調整」を分ける。1フェーズは1〜2日で終わる大きさに。
6. フェーズごとに遊んで、番号と理由で答える。決まったことは計画のメモと企画まとめの両方に。
7. 「忘れないようにメモ」は Issue にし、マイルストーンを付ける。AI はフェーズを閉じる前に残りの Issue を並べる。
8. 大量に作るものは、人が見て直せる表やアーティファクトにする。試し描き・試作を数個見せてから量産する。
9. 調整の前提を決めてから、最後にまとめて合わせ、固定する。固定した数字はテストで守る。
10. 調整のあとに足すものは、「難易度を変えるか」を先に決める。
11. 操作の不満は小さくても、すぐ言う。
12. 長い計算は、締め切りと「寝る前にどこまで」を書く。
13. **（パズル）素材や部品ごとに「いちばん素直な部品（鉛）では、なぜだめか」を企画で1行書き、フェーズ0〜1でソルバーを使って「その素材でしか解けない問題」が作れるかを確かめる。** 作れない素材は、ルールを変えるか外す。
14. **（パズル）ソルバーの限界を最初に測る。** 「手持ち何個・器どの大きさまでなら何秒」の表を作り、問題とエディタの大きさの上限をそこから決める。ヒントを総当たりで出すなら、その上限を超える問題は作らない（または作った人の手順を残す）。
15. **（生成）量産の前に、計算の目安と人の順位が合うかを数問で確かめる。** 合わなければ、人が選ぶ前提で数を減らす。数は「作れる量と質」が分かってから決め、人が遊ぶ回数の上限も先に決める。
16. **（生成）「同梱するだけ」か「その場で作る」かを先に決める。** 速くする作業は、その場で作るときだけ。

### 頼むときのひな形（今回の分を足した）

```
■目的：何を作る・直すか
■正の文書：企画まとめのリンク（決まったことはここに書き足す）
■変えないこと：遊びの柱、ジャンルのお約束、固定した数字 など
■前提：試すときの条件、遊び方（ふつうの人／工夫する人）
■目標：数字と、その測り方（何を相手に、何回測るか）
■素材・部品の役目：それぞれ「鉛（いちばん素直な部品）ではできないこと」
■大きさの上限：ソルバーやヒントが間に合う範囲
■任せてよいこと：数値の当てはめ、生成、テスト、絵
■必ず確認してほしいこと：遊びの柱にかかわる変更、全体に効く値の変更、2通りに読める指示
■人が遊ぶ回数：試作は○回まで、1回○問
■残っているメモ：Issue 番号（フェーズの終わりに読み上げる）
■報告に入れてほしいこと：足した機能の場所、目安と人の順位のずれ、作れなかったもの
■締め切り：日本時間 ○月○日 ○時
■説明：やさしい日本語で、結論から
```
